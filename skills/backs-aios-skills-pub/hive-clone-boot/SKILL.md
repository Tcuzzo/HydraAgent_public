# Public hive boot

1. Load `optimus` for the invariant floor, then the intent and context skills needed
   for the current task. Use the active runtime's supported loader.
2. Verify the actual source revision, tool catalog and configured model routes.
3. Select a public generic profile from `roster.yaml` and `agents/`. These files do
   not assert that private servers, named GPUs or deployment services exist.
4. Assign explicit scope, owner, deadline and evidence requirements. Bind only
   authorized communication destinations and the existing execution policy.
5. For consequential review, use independent configured author/judge identities
   and families. Record unavailable independence; do not block ordinary single-
   model work or claim a different provider label proves a different model.
6. Report implemented, tested and deployed states separately, using present
   evidence. Preserve checkpoints and make retry/reset behavior finite.

`references/HIVE_CLONE_HANDOFF.md` describes the public workflow.
`CHECKLIST.md` lists checks to perform on each actual installation; it carries no
historical success claims. Private canon and essence remain outside this package.
Model choices belong in operator configuration, never hardcoded hardware/vendor
rules in the profile. Project and upstream attribution remain in repository credits.
